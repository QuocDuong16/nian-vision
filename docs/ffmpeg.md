# FFmpeg in Nian Vision

Decision record: `docs/adr/0002-ffmpeg-integration-strategy.md`. This page
is the practical reference.

## Pinned facts

| Item | Value |
|---|---|
| Header/ABI pin | FFmpeg **8.0.3** (libavformat 62, libavcodec 62, libavutil 60; tarball sha256 `6136812ea6d4e68bdba27e33c2a94382711cdf4f8602ffef056ff792bd6f9818`) |
| Bindings | generated by bindgen from vendored headers, **committed** to `crates/nian-ffmpeg-sys/src/bindings.rs` |
| Linking | dynamic only, never static |
| License mode | LGPL (no `--enable-gpl`, no `--enable-nonfree` in shipped builds) |
| Runtime check | worker refuses to start on ABI major mismatch |
| Native logs | `AV_LOG_QUIET` forced at startup (secret boundary, below) |

## Library discovery (build time)

`nian-ffmpeg-sys/build.rs` resolves link libraries in this order:

1. `NIAN_FFMPEG_LIB_DIR` — directory containing `libavformat.so` /
   `avformat.lib` etc. (works for Windows vcpkg layouts:
   `vcpkg install ffmpeg[avformat,avcodec]` then point at
   `vcpkg/installed/x64-windows/lib`).
2. `<repo>/.ffmpeg-lib/` — created by `scripts/setup-ffmpeg-linux.sh` on
   Linux systems that have FFmpeg runtimes but no `-dev` packages (it
   symlinks `libavformat.so` → `libavformat.so.62`, ...).
3. `pkg-config` (`libavformat`, `libavcodec`, `libavutil`) for standard
   dev-package installs.

## Linux release runtime

Production Linux releases do not use the developer machine's FFmpeg installation.
`scripts/release/build-ffmpeg-linux.sh` downloads the exact FFmpeg 8.0.3 tarball,
verifies the pinned SHA-256, builds shared libraries with GPL/nonfree disabled and
stores the exact configure flags plus generated `config.h` as release evidence.

Before packaging, `validate-ffmpeg-config.mjs` mechanically checks the license and
shared/static mode, then `nian-media-ffmpeg`'s real integration suite runs against
that candidate runtime. Staging copies only the ABI libraries used by the worker:

* `libavformat.so.62`
* `libavcodec.so.62`
* `libavutil.so.60`

The pre-bundle release worker contains `$ORIGIN/../lib/nian-vision` RUNPATH, so
staging resolves those libraries from its application-owned runtime rather than
through `LD_LIBRARY_PATH` or a developer package manager. Tauri/linuxdeploy may
rewrite the packaged worker RUNPATH to `$ORIGIN/../lib` and may copy byte-identical
FFmpeg SONAMEs into legacy `/usr/lib`. The release normalizer operates on the completed
AppImage before smoke validation: it removes only byte-identical legacy FFmpeg copies,
restores the worker RUNPATH to `$ORIGIN/../lib/nian-vision`, revalidates the private
FFmpeg closure under `/usr/lib/nian-vision`, and repacks with the original AppImage
runtime. Staging verifies the dynamic dependency closure with development overrides
removed and exercises HELLO, fixture probe and `playback.prepare` through the staged
worker. The AppImage is extracted and smoke-tested again after packaging. Exact flags,
LGPL text and third-party notices are shipped with the release.

## Windows release runtime

The Windows x86_64 release path builds the same FFmpeg 8.0.3 source pin on the
explicit `windows-2022` runner using FFmpeg's MSVC toolchain. The production build
remains shared/LGPL-only and emits the MSVC import libraries consumed by Rust plus
the application-local runtime DLLs:

* `avformat-62.dll`
* `avcodec-62.dll`
* `avutil-60.dll`

`scripts/release/stage-windows.ps1` recursively inspects `dumpbin /dependents` for
the worker, the three FFmpeg DLLs and, after it is compiled, the desktop executable.
Dependencies must resolve from the staged application directory, Windows API-set /
System32, or an explicitly copied Visual C++ redistributable DLL from the selected
MSVC toolchain. MSYS2, vcpkg and developer build paths are never runtime authority.

The clean staged worker smoke removes `NIAN_FFMPEG_LIB_DIR` and does not add a
developer FFmpeg directory to `PATH`. NSIS installs the same DLL closure beside the
desktop/worker; the installed-runtime smoke hashes those files against the exact
staged inputs and repeats the worker media fixture checks. FFmpeg configuration,
license text, source checksum and build flags are carried into the platform manifest
and then the combined GitHub Release metadata. Windows remains unmarked as validated
until the hosted Windows tag-release path completes successfully.

## Regenerating bindings

Only needed when bumping the FFmpeg pin or extending the whitelist:

```bash
scripts/fetch-ffmpeg-headers.sh   # downloads + sha256-verifies, vendors headers
cargo run -p bindgen-gen          # requires libclang; writes src/bindings.rs
```

The whitelist lives in `tools/bindgen-gen/src/main.rs` (~36 functions,
~12 types). Keep it minimal: every symbol added is audit surface.

## Runtime safety model

* `nian-media-ffmpeg` validates `avformat_version()`/`avcodec_version()`/
  `avutil_version()` majors against the compiled-in constants at first use
  and errors out (`MediaError::AbiMismatch`, preserved structurally) on
  mismatch.
* `avformat_network_init` runs once per process.
* Blocking operations (open, find_stream_info, read) consult an
  `AVIOInterruptCB` backed by `InterruptHandle` — cancellation and
  deadlines work for both local files and RTSP. `MatroskaMuxer` retains its
  own clone of the handle for the full output-context lifetime and passes
  the callback to protocol-level I/O via `avio_open2`, so the callback
  target can never dangle.
* All `AVFormatContext`/`AVPacket` ownership is wrapped: `MediaInput` and
  `MatroskaMuxer` free everything in `Drop`; no raw pointer escapes the
  crate.
* A segment counts as finalized only when **both** `av_write_trailer` and
  the final `avio_closep` flush/close succeed; failures propagate as
  `MediaError::WriteFailed` and leave the file eligible for partial-file
  recovery.

## Native log policy (secret boundary)

libav* writes diagnostics straight to stderr through its own pipeline;
Rust-side redaction cannot see that traffic, and RTSP handshake logging can
include the full connect URL — credentials included. Startup init therefore
pins the native level to `AV_LOG_QUIET`
(`nian_media_ffmpeg::logging`, asserted by `native_logging_quiet()` and by a
worker integration test that feeds a sentinel credential through
`probe --rtsp-from-env`).

To enable native diagnostics later, install an `av_log_set_callback`
trampoline that filters credential-bearing lines before forwarding to
`tracing`. That callback receives a C `va_list` with no stable safe FFI, so
it requires a reviewed `unsafe` design first — simply raising the log level
is not an acceptable shortcut in production.

## Manual RTSP smoke test (Tapo C200)

Credentials must not appear in argv (process listings are world-readable):

```bash
NIAN_VISION_RTSP_URL='rtsp://<user>:<password>@<camera-ip>:554/stream1' \
  ./target/debug/nian-media-worker probe --rtsp-from-env
```

The URL is never logged; error paths print the redacted host only.

## Why not ffmpeg-next / ffmpeg-the-third?

See ADR-0002 for the full rationale: owned sys layer + owned safe wrapper
avoids a duplicate abstraction, keeps the audited surface at ~36 functions,
and removes a transitive dependency whose supported-version claims we would
have to re-verify anyway.
