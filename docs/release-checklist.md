# Nian Vision v1 release checklist

Record the exact tag, commit SHA, OS image/VM and result for every run. A checkbox is evidence only when the step was actually executed. Do not reuse a tag after changing source.

Final source candidate: `1.0.0` / `v1.0.0`, based on immutable RC61 plus a separate Performance modal fix. RC1 through RC61 remain immutable; RC59 was a consumed version-mismatch failure and was not rewritten. The final source commit changes the version and release documentation separately from the modal fix. This checklist records release evidence, not an automatic assertion that its unchecked steps passed. Do not move, delete or reuse a consumed tag.

## Pre-tag authority

- [ ] Final version commit is on the authoritative Forgejo default branch; every version surface is `1.0.0` and Cargo.lock is synchronized.
- [ ] Forgejo normal CI is green: fmt, check, full workspace/all-feature Clippy, workspace tests, cargo-deny, frontend lint/typecheck/Vitest/build.
- [ ] Code review accepts M15 and confirms no v2 feature scope.
- [ ] `node scripts/release/version-check.mjs --tag <candidate-tag> --require-clean` passes on the exact release commit.
- [ ] Mirror configuration is known to propagate tags and `RELEASE_MIRROR_ACTOR` is configured.
- [ ] Production updater public key/signing secrets are provisioned in the protected GitHub environment.
- [ ] If `REQUIRE_WINDOWS_AUTHENTICODE=true`, valid Authenticode credentials/timestamp URL are provisioned.

## Media lifecycle and soak gate

- [ ] `pnpm media:gate` passes on the exact RC commit. This pins shared-ingest connection ownership, reconnect single-flight behavior, safe/backward-compatible per-source Media diagnostics, reliable-vs-realtime backpressure isolation, pre-roll timestamp mapping, Event disable/disconnect authority settlement, repeated Live View MSE cleanup and repeated Grid↔Focus profile switching. The 20-cycle MSE acceptance specifically proves teardown reaches `endOfStream()`, revokes the object URL and returns the frontend MSE-session count to zero every cycle; production cleanup also aborts transport work, detaches the `SourceBuffer`, clears `<video src>` and calls `load()`.
- [ ] On a cold Windows app startup, open Performance → Media soak and Start soak **before any media use** to capture the first sample as `B0`. Open/close one camera once, let it settle, then click **Mark warm baseline** to capture `Bw`. Run the 20-cycle sequence and click **Mark media closed** only after the last session is closed; the UI requires `Bw` before enabling the idle marker. The marker captures an immediate timestamped sample; +30s/+120s checkpoints are selected from samples within 10 seconds of each target and compared against `Bw`, not `B0`. Late samples are marked unavailable rather than being mislabelled as 30-second evidence. Use Performance → Media soak to capture five-second samples capped at 1,440 (~2 hours), then auto-stop without evicting the original baseline and retain baseline/current/peak app RAM, linear RAM trend/hour, recent five-minute RAM span, media-worker peak, packet-buffer peak, CPU peak, system-RX peak, mounted-video/MSE/browser-buffer peak and ingest-generation delta while the popover is closed or open. Export the aggregate-only schema-v1 JSON evidence (both marker timestamps plus B0/Bw and recovery deltas) for the RC record. Review evidence quality before judging a plateau: process snapshots older than 2.5 seconds are skipped and counted, failed/stale Media diagnostics are `null` rather than invented zero queue/generation values, and the report includes media-unavailable sample count and maximum sampling gap. A missing or reset generation counter produces an unavailable delta, not a misleading zero; repeat the run or corroborate with worker logs when coverage is insufficient. Do not interpret a run started after media warm-up as a genuine cold B0. After 20 Live View open/close cycles, memory must plateau rather than grow monotonically; target final memory is no more than `Bw + 30 MB`, no more than `Bw + 50 MB` after 30 seconds idle and about `Bw + 25–30 MB` after 120 seconds idle.
- [ ] H.265/G.711 codec gate: verify that the release-bundled Windows/Linux FFmpeg build includes the HEVC parser, AVC/HEVC decoders and G.711 A-law/μ-law decoders, not only the developer machine’s system FFmpeg. Run `pnpm media:gate` against the exact candidate commit; its HEVC/G.711 fixture tests must prove original Matroska packet copy, `hvc1` browser MP4, Event-clip two-segment composition/playback, both WAV laws and session-scoped HTTP range/revocation. On a real camera, record and play H.264/AAC and H.265/G.711 A-law/μ-law where available, checking video seek, audible audio, mute/volume, playback-rate changes and A/V sync across event pre-roll and clip boundaries. Repeat H.265 Live and playback on Windows machines both with and without usable HEVC decoding capability; unsupported WebView decoding must surface a clear error rather than claim successful playback. Keep the camera’s original Matroska archive intact even if playback fails. No camera hardware results can be inferred from synthetic codec fixtures.
- [ ] Camera-provided Person event classification: on a Tapo model/firmware that actually exposes `PeopleDetector/IsPeople` over ONVIF, confirm Person started/ended appear separately in Event Review, `IsMotion` does not claim Person, and both Person events share the same aggregate motion clip rather than creating another recording or native notification. Validate the original EventIndex v2 upgrades atomically to v3 without losing IDs, fingerprints, source identity or visibility. Inject failure on the second (aggregate) insert and verify both source/aggregate rows roll back together; replay must create each once and the Person row must never be orphaned from a failed aggregate commit. An app push notification by itself is not an ONVIF person-event feed. No local person recognition, camera tamper or baby-cry detector is claimed.
- [ ] Local Motion opt-in: with ONVIF Events disabled and recording storage configured, enable Local Motion on a camera. Confirm `motion.start/status/ack/stop` share Grid substream with Live (fallback main if no sub), refuse detector admission until main pre-roll is retained (including when the main stream/storage fails but Grid stays healthy), independently retain main pre-roll for archive, persist distinct start/end events, emit only one notification per committed start, and produce Event Review footage. Disable during activity and confirm bounded post-roll and no continuation; a dead worker lease must be reacquired, an ACK reply lost after EventIndex commit must be safely retried without duplicate episodes or false sequence gaps, and a reset worker sequence must never silently discard new events. A hard kill before EventIndex commit can lose the worker-only in-memory transition and must be reported as a limitation, not a successful durability test. Verify preference survives app restart, toggling ONVIF ON while Local Motion is enabled is rejected, and reverse is also rejected. Cameras must distinguish Desired On from actual `monitoring`/`backoff`/`failed`/waiting states without showing a credential or mistaking an unavailable worker for idle; verify this updates on bounded five-second diagnostics polling. Confirm a brief (under five seconds) still interval between two Local Motion bursts produces a single MotionStarted/Event clip, while a sustained quiet interval ends the episode; existing stored episodes are not rewritten. In Event Review, open a clip and verify its approximate detection timestamp is highlighted with a ±3-second band, opens three seconds before detection when possible, and offers Jump to detection; ambiguous or out-of-range times must not produce a fictitious marker. Check Performance at narrow and wide window sizes: the centered 80vw × 80vh modal must show media diagnostics without nested scroll traps or horizontal clipping; keyboard focus, Close, Escape and backdrop dismissal must work. Validate false positives and CPU/RAM on hardware: this is generic scene motion, not people/tamper/cry recognition. The Nian detector derives an end from quiet frames; Tapo phone push notifications alone do not contain reliable start/end pairs.
- [ ] Run at least 60 minutes Recording + Live, repeated Focus/Unfocus, 20–50 playback open/close cycles, and 4/8/16-camera multiview where hardware is available. Keep the Media soak capture running and separately record actual network/RTSP connection count where the OS/camera exposes it; do not accept screenshots without a baseline or a bounded sample history.
- [ ] Performance → Media proves bounded ownership during the soak: leaving Live View returns mounted video elements and active MSE sessions to zero; buffered browser media returns to zero; queue/ring bytes stay bounded; `generation_starts` increases only for real ingest generations/reconnects. Per-source rows must identify only safe media shape/state (`MAIN`/`SUB`, lifecycle, codec, resolution, average fps, retainers, subscriber policy, queue/ring bytes) and must never expose the RTSP URL or credentials. Recording + Focus + Event pre-roll resolve to one main source, Grid resolves to the configured sub source, and concurrent main/sub consumers use at most main + sub (one source total when both profiles resolve to the same endpoint). ONVIF motion monitoring is an event/control-plane consumer and does not itself open an RTSP motion-analysis stream in v1.
- [ ] Any camera disconnect/reconnect must replace one failed ingest generation with one new generation. A slow Live consumer may drop/resync at the next keyframe without losing reliable Recorder packets or stalling the shared ingest.

## GitHub final release workflow

- [ ] After final-source Forgejo CI, review and required acceptance, create immutable `v1.0.0` on the exact final version commit. Do not move or reuse RC1 through RC61 or a consumed final tag; source/tag cross-pairing is forbidden.
- [ ] GitHub tag resolves to exactly the same commit as Forgejo.
- [ ] Linux build/sign jobs pass.
- [ ] Windows build/sign jobs pass.
- [ ] Both platform candidates are required by final verification.
- [ ] Worker sidecar and FFmpeg runtime are present in both packages.
- [ ] Updater signatures verify with the configured public key.
- [ ] `SHA256SUMS.txt` verifies every public artifact it names.
- [ ] `latest.json` names real published candidate artifacts and has the expected version/signatures.
- [ ] Verified final GitHub Release is `prerelease=false` and becomes production `latest` only after both signed platform artifacts and publication checks pass.

## Clean Windows x86_64 machine/VM

- [ ] NSIS current-user install succeeds from a path containing spaces.
- [ ] First startup succeeds with no cameras and no fake failure state.
- [ ] Performance telemetry matches Windows reality closely enough to diagnose ownership: the compact footer reports the Nian desktop host rather than the whole tree, the detail popover lists each owned PID/role separately (desktop, WebView2 roles, media workers), and the sum of the displayed rows equals the reported Nian Vision total. Compare the desktop PID and at least one WebView2 PID against Task Manager; record any material discrepancy instead of accepting an unexplained aggregate.
- [ ] UI resize acceptance: verify the default 1280×800 window, a medium rail layout (roughly 900–1100 px wide), and the 720×520 minimum window. Navigation must remain reachable, dialogs must fit/scroll inside the viewport, bottom navigation must not cover actionable content, and Cameras/Live View/Events/Timeline/Storage/Settings must remain operable without horizontal page overflow.
- [ ] Add a camera manually; RTSP probe succeeds.
- [ ] Start/stop recording; finalized media is playable. Force or observe a retryable RTSP open/read timeout and verify Cameras/Live View say Reconnecting with a human-readable reason and retry count instead of exposing raw `backoff`/wire codes; after recovery or a clean Stop, the stale failure reason must disappear.
- [ ] Kill/restart desktop while Recording Desired is On; Desired restores once.
- [ ] Live View opens and closes; selected camera layout and Fit/Native preference survive tab remount while the old sessions close and fresh sessions reopen on return. Verify no hidden live session remains active after leaving the tab. During an in-session RTSP hiccup, `backoff -> connecting -> live` must keep the same video/MSE presentation mounted (a brief frozen frame is acceptable; a blank Connecting tile/remount is not), and a stable >=10-second live period must reset the consecutive reconnect budget. Fit tile remains default for a fresh preference, Native pixels visibly avoids upscale when the tile has spare room, and Diagnostics reports source/display/DPR scaling without changing the live session.
- [ ] Playback opens/seeks/closes.
- [ ] Compatible camera ONVIF discovery/provisioning succeeds.
- [ ] Compatible camera PTZ works; movement stops on lifecycle teardown and never restores by itself. On Tapo C200 V5 verify multiple/partial velocity-space advertisements do not poison a later complete pan/tilt candidate, and verify repeated ContinuousMove/Stop commands remain reachable after pairing even when the camera closes HTTP sockets between SOAP responses. Any remaining failure must retain the typed services/profiles/options stage instead of generic `onvif_protocol`.
- [ ] Compatible camera Event monitoring persists normalized Events and Event Review can open correlated footage where available. On Tapo C200 V5/1.4.6 verify the fingerprint-gated adapter can probe same-host TCP 2020 PullPoint, remains Polling rather than Backoff on valid vendor extensions/duplicate state echoes, and record observed CellMotion/People/Smart Event/Line Cross transitions without exposing raw source tokens. If it fails, record the stage-specific `event_control_*`, `event_pull_*`, or `event_renew_*` code.
- [ ] Independent motion Event capture: with manual Recording Desired Off, enabling Events retains the camera's bounded compressed main-stream pre-roll ring without continuously writing event media to disk. When motion starts, the event recorder subscribes to the same main ingest, atomically seeds about five seconds of keyframe-aligned compressed history, continues through the motion interval and five-second post-roll, then stops while the in-memory ring remains ready for the next event. The resulting clip appears only in Event Review under `.nian/event-clips`, never in Timeline. While manual Recording is already On, motion must not stop/restart/promote or otherwise alter the manual recorder; manual footage remains continuous and the Event gets its own clip. A continuous >5-minute motion episode must expose multiple Event Review clip parts, each no longer than five minutes, with Previous/Next navigation and no hidden continuation parts. Disable Events during active motion and verify the current episode receives at most the bounded five-second post-roll, then stops with no continuation part after Desired Off. Also interrupt ONVIF Event monitoring during active motion and verify stale motion authority is cleared, the current episode settles with bounded post-roll, and recovery does not manufacture five-minute continuation clips from the pre-disconnect state. Event Review must change from unavailable to Recording available automatically after finalization. Verify retention skips an actively playing Event clip and old Event clips are removed according to Event age/quota without deleting the corresponding manual Timeline recording.
- [ ] Local notification appears when enabled; missing native notification support/failure remains non-fatal. Run the delivery-timeout isolation regression repeatedly on Windows and verify observing `delivery_timeouts` implies the timed-out native delivery has already been terminated.
- [ ] Close hides to tray while Recording/Events/notifications continue and Live/PTZ settle.
- [ ] Suspend/Resume: Recording/Event Desired restore without duplicate workers; Live/PTZ do not restore.
- [ ] Second manual launch activates existing instance; startup-hidden duplicate does not unexpectedly show it.
- [ ] Launch-at-login remains user-controlled and startup-hidden restores Desired Recording/Event state.
- [ ] Tray Quit leaves no owned media worker or notification helper.
- [ ] Install/update over a previous build preserves camera configuration, credential usability, Recording Desired, Event Desired/bindings, storage settings and notification preference.
- [ ] Uninstall removes application binaries/autostart registration but does not delete recordings or authoritative application data contrary to documented policy.

## Clean Linux x86_64 machine/VM

- [ ] AppImage starts without repository checkout, `NIAN_FFMPEG_LIB_DIR` or developer library paths.
- [ ] First startup succeeds with no cameras.
- [ ] Bundled media worker is executable and resolves bundled FFmpeg runtime.
- [ ] Manual camera add and RTSP probe succeed.
- [ ] Recording, restart Desired restore, Live View and playback succeed.
- [ ] Compatible-camera ONVIF provisioning/PTZ/Events are exercised where hardware is available.
- [ ] Event Review works and missing recording is a normal unavailable state.
- [ ] Desktop notification succeeds when a notification service exists; unavailable service remains non-fatal.
- [ ] Close-to-tray and Quit semantics are correct; controlled shutdown leaves no owned media worker/helper.
- [ ] AppImage updater handoff succeeds from a signed candidate and persisted Desired state restores on next startup.

- [ ] All hardware-dependent results are explicitly recorded, including Tapo C200 items that were not exercised.
- [ ] Required artifacts exist for Windows and Linux and versions match tag.
- [ ] `release-manifest.json` commit equals expected Forgejo release commit.
- [ ] Global checksums and updater signatures verify after downloading from GitHub Release.
- [ ] No release asset contains configured secret sentinel or development path dependency.
- [ ] `RELEASE_NOTES.md`, README, support matrix and known limitations match the artifact being released.
- [ ] No mandatory blocker remains.

The final source version commit follows the separate Performance modal fix commit. It must pass Forgejo CI, final review and the applicable release acceptance above before creating immutable `v1.0.0`. Build and sign fresh final artifacts from that exact commit; do not reuse RC binaries or move an already-tested tag.
