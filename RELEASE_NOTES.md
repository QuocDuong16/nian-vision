# Nian Vision 1.0.0-rc.40
Nian Vision v1 is a local-first desktop NVR for configured IP cameras on Windows x86_64 and Linux x86_64.

RC40 follows manual Windows C200 acceptance of immutable RC39. Motion Event pairing now authenticates and validates the ONVIF Events service directly instead of first requiring ONVIF Media discovery, so a manually configured RTSP camera can pair compatible PullPoint motion events even when its ONVIF implementation omits or rejects Media service discovery. Unsupported Events now report an Events-specific error. Live View lowers the post-initial fragmented-MP4 target from one second to 500 ms and polls the localhost manifest every 250 ms, reducing application-introduced live latency while retaining RC39 timestamp-offset, monotonic movie-fragment sequence, live-edge catch-up, continuity, and bounded-cache protections. Recording and the protected FFmpeg release contract are unchanged.

RC39 remediates the remaining manual Windows C200 Live View failure observed after immutable RC38: video rendered for roughly 20–30 seconds but stayed about five seconds behind live and then WebView2 raised a media-element failure. RC38 correctly stopped appending repeated MP4 initialization/index/footer boxes, but each worker MP4 is still independently muxed with a zero-based media timeline and fresh movie-fragment sequence numbers. RC39 keeps the first live chunk keyframe-started, then rotates later chunks at the one-second target without waiting for another keyframe; the browser places each zero-based chunk explicitly with `SourceBuffer.timestampOffset`, rewrites `mfhd.sequence_number` monotonically across appended chunks, catches up near the live edge when latency grows, trims only media safely behind the playhead, and treats missing fragment continuity as a fresh-session boundary instead of appending dependent H.264 across a gap. Recording, playback files, and the protected FFmpeg release contract are unchanged.

RC38 remediated the first continuous-playback failure after immutable RC37 by parsing each worker MP4, appending `ftyp`/`moov` initialization metadata only once, appending only `moof`/`mdat` media boxes thereafter, excluding per-file `sidx`/`mfra` indexing/footer boxes from the MSE byte stream, and lowering the live fragment target from two seconds to one second. Manual C200 acceptance then showed that the remaining per-file zero-based timeline and keyframe-bound rotation still produced about five seconds of latency and a media-element failure after roughly 20–30 seconds.

RC37 remediated manual Windows C200 acceptance failures discovered after immutable RC36: live fragmented-MP4 and recording Matroska packet-copy segments normalize missing/duplicate/backwards RTSP timestamps at the mux boundary, including synthesizing a missing DTS or PTS from the available timestamp. Recording rotation continues to use the original input media clock. Live write failures are split into mux-write, packet-size and fragment-limit categories for deterministic follow-up. The v1 codec contract remains H.264 packet-copy only; RC37 does not claim H.265/transcoding support.

## Main capabilities

- Manual RTSP camera configuration and ONVIF discovery/provisioning.
- Up to 8 simultaneous H.264 stream-copy recording sessions with local retention and crash/partial recovery.
- Up to 4 independent Live View sessions and local playback/timeline review.
- Optional ONVIF PTZ continuous pan/tilt and capability-gated zoom.
- Up to 16 optional ONVIF PullPoint Event-monitoring sessions with normalized local Event history.
- Event Review with existing-recording correlation and five-second pre-roll when footage exists.
- Optional local desktop MotionStarted notifications with bounded dispatch/rate limiting.
- Single-instance desktop lifecycle, close-to-tray, launch-at-login, Windows suspend/resume handling and signed in-app updater artifacts.

## Privacy and security

Camera passwords remain in the native OS credential store; ordinary SQLite stores only opaque credential references. Recordings and Event history remain local. Nian Vision v1 has no cloud video upload, remote-access service or cloud notification service.

## Upgrade notes

Authoritative settings migrations preserve camera definitions, credential references, Recording/Event Desired state, PTZ/Event bindings, storage settings and notification preference. Corrupt authoritative settings are never silently replaced. Recording and Event indexes are derived and may be boundedly quarantined/rebuilt without deleting camera settings or footage.

## Known limitations

v1 requires H.264 and does not transcode or support H.265. ONVIF feature availability depends on the camera. There is no macOS/mobile release, remote/cloud access, AI/person/object detection, motion-triggered recording, generated clips/thumbnails, presets/tours/talkback, email/webhook/cloud push notifications or notification scheduling. See `docs/known-limitations.md` for the normative list.

The final `v1.0.0` tag must not be created until M15 acceptance and the clean Windows/Linux release-candidate checklist are complete.
