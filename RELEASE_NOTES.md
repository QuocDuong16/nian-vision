# Nian Vision 1.0.0-rc.24
Nian Vision v1 is a local-first desktop NVR for configured IP cameras on Windows x86_64 and Linux x86_64.

RC1 through RC9 remain immutable historical release attempts. RC7 proved the deterministic MSYS2 tar/xz extraction path and reached the Windows FFmpeg source build, where uncontrolled Windows/MinGW make behavior corrupted the MSVC dependency command. RC8 pinned the intended FFmpeg build tools and added generated `CCDEP` validation but failed on a representation-level MSVC path assertion. RC9 proved the replacement semantic Visual Studio/MSVC authority on the real `windows-2022` runner, then exposed missing hosted `/usr/bin/make`. RC10 is an immutable consumed attempt: it successfully provisioned pinned official MSYS2 `make` 4.4.1-3 and `diffutils` 3.12-1, preserved the sanitized selected-MSVC plus `/usr/bin` authority, and reached the aggregate FFmpeg Windows toolchain probe, where the large generated multi-line Bash body failed when transported as a `bash -lc` command-line argument. RC11 is an immutable consumed attempt: it moved generated Bash programs to deterministic UTF-8/LF temporary `.sh` files with mandatory `bash -n`, then passed Windows FFmpeg download, SHA-256 verification, extraction and configure before exposing a PowerShell post-configure collection-cardinality bug. RC12 is now an immutable consumed attempt: it preserved RC10/RC11 hardening and passed Windows preflight, source SHA-256 verification, extraction, configure, collection diagnostics, CCDEP on-disk validation and GNU make CCDEP expansion. RC12 then began real MSVC compilation and failed while compiling `libavformat/cbs.o` with `fatal error C1001: Internal compiler error`; the later GNU make Error 127 was not the root cause. FFmpeg upstream commit `6a59c847b50c6bc30630df7fca56ccd6cd8a5a8c` (`configure: Redo enabling cbs in lavf`) explains that the CBS type table can be empty when lavf does not select APV/AV1 CBS implementations, which is illegal C and may trigger an MSVC internal compiler error. RC13 is now an immutable consumed attempt: it successfully applied that exact upstream CBS-in-lavf backport, passed post-configure CBS macro validation, passed the targeted Windows `libavformat/cbs.o` MSVC regression compile, passed the full Windows FFmpeg compile and install, then failed only in post-install release validation because the validator incorrectly expected global `CONFIG_NETWORK` in `config_components.h`; FFmpeg 8.0.3 actually generates `CONFIG_NETWORK` in `config.h`. The observed failure did not prove networking was disabled or that `CONFIG_NETWORK` was zero. RC14 is now an immutable consumed attempt: it correctly validated `CONFIG_NETWORK` from `config.h`, passed CBS validation, passed the targeted `libavformat/cbs.o` MSVC regression compile, completed the full Windows FFmpeg compile, linked the DLLs and installed them, then failed only in post-install component validation because the release configure contract requested nonexistent protocol `rtsp`. FFmpeg 8.0.3 provides RTSP as the `rtsp` demuxer, not as a URLProtocol, so `CONFIG_RTSP_PROTOCOL` was an invalid expectation; this failure did not mean networking or RTSP demuxing was disabled. RC15 is now an immutable consumed attempt: it removed the nonexistent RTSP protocol request, retained the RTSP demuxer, and moved resolved requested-component validation to immediately after configure, before the CBS probe or full compilation. FFmpeg passed that remediation; RC15 then failed later in Windows Rust quality because Rust 1.98.0 MSVC had been installed with `--profile minimal` without `rustfmt`, so `cargo fmt --all --check` failed because `cargo-fmt.exe` was absent. `clippy` was likewise not explicitly provisioned and is treated as the latent deterministic sibling. RC16 is now an immutable consumed attempt: it explicitly provisioned `rustfmt` and `clippy` and successfully progressed into Windows Rust quality, where `tauri-build` then failed because the repository did not contain the required `apps/nian-desktop/icons/icon.ico`. Independently, Linux reached actual AppImage smoke validation with the intended private FFmpeg runtime present under `/usr/lib/nian-vision`, but linuxdeploy had also copied duplicate FFmpeg SONAMEs into legacy `/usr/lib`, violating the release layout contract. RC17 added the required Windows ICO bundle asset and normalized the completed AppImage by deleting only byte-identical legacy FFmpeg duplicates. It then exposed two later deterministic blockers: Windows `cargo clippy --all-targets -- -D warnings` rejected a `NaiveDate` import that is used only by a Unix-gated test, and Linux AppImage smoke proved Tauri/linuxdeploy had rewritten `nian-media-worker` RUNPATH to `$ORIGIN/../lib` instead of the required `$ORIGIN/../lib/nian-vision`. RC18 removed that cross-platform unused import and restored the exact private worker RUNPATH inside the extracted AppDir before repacking, while refusing unexpected RUNPATH states and revalidating the private FFmpeg closure. Hosted RC18 then exposed two later boundary failures: Windows workspace tests used a Unix-only absolute storage path fixture, and the Linux signing job downloaded the already-smoked AppImage through the GitHub artifact boundary with its executable bit cleared. RC19 used a platform-native absolute path for the config unit test and restored plus verified AppImage executable mode immediately after download, before signing and signed smoke. Hosted Windows workspace tests then exposed a second Unix-only storage-root fixture in the camera-service integration suite, while Linux reached real desktop startup smoke and failed because the minimal smoke host lacked the system `libEGL.so.1` graphics loader intentionally excluded by the AppImage graphics-driver compatibility boundary. RC20 removed the remaining Unix-only storage/output fixtures, added their Windows regression, and provisioned the host EGL runtime for Linux AppImage smoke. Hosted Windows workspace tests then exposed a separate test-harness transport bug: worker-supervisor Bash fixtures passed a native Windows temporary `.sh` path as a `bash -c` command string, so the stub never emitted a valid JSON hello frame and 17 supervisor tests failed at handshake. RC21 executed each stub as a Bash script-file argument with slash-normalized native paths, but hosted Windows still failed all meaningful supervisor fixtures at hello decoding; its sole passing version-mismatch test was a false positive because it accepted any protocol error. Linux meanwhile passed the new host EGL check and then failed when WebKit attempted to load system `libGLESv2.so.2`. RC22 uses the existing preflighted `C:\msys64\usr\bin\bash.exe` plus `cygpath -u` contract for Windows fixtures, makes the mismatch test require the real unsupported-version diagnostic, and provisions/verifies both `libEGL.so.1` and `libGLESv2.so.2` on unsigned and signed Linux smoke hosts without bundling those graphics loaders. Hosted RC22 Windows then failed all-target Clippy on a cfg-gated `return String::from_utf8(...)` that is needless once the non-Windows branch is compiled out. Linux workspace tests separately exposed a test-only deadlock race: the static retention pre-delete gate was visible to every parallel `StorageManager`, so a sibling retention test could consume the gate signal/resume pair and strand the intended race worker. RC23 moves Windows script-path conversion into cfg-specific helper expressions with no needless return, removes the global retention test gate, and stores the one-shot gate on the exact `StorageManager` instance under test. Hosted RC23 then passed those earlier blockers but exposed a Windows release-verifier fixture boundary bug: the signed ASCII `artifact.bin` had no binary Git attribute, so Windows checkout could rewrite its LF newline to CRLF while the Minisign signature still authenticated the original LF bytes. Linux signed AppImage smoke separately reached system-tray initialization and failed on missing `libayatana-appindicator3.so.1`. RC24 makes that signed fixture byte-stable with `.gitattributes`, adds a regression for the binary attribute, and explicitly provisions/verifies `libayatana-appindicator3-1` alongside the existing EGL/GLES smoke-host runtime prerequisites.

## Main capabilities

- Manual RTSP camera configuration and ONVIF discovery/provisioning.
- Up to 8 simultaneous H.264 stream-copy recording sessions with local retention and crash/partial recovery.
- Up to 4 independent Live View sessions and local playback/timeline review.
- Optional ONVIF PTZ continuous pan/tilt and capability-gated zoom.
- Up to 16 optional ONVIF PullPoint Event-monitoring sessions with normalized local Event history.
- Event Review with existing-recording correlation and five-second pre-roll when footage exists.
- Optional local desktop MotionStarted notifications with bounded dispatch/rate limiting.
- Single-instance desktop lifecycle, close-to-tray, launch-at-login, Windows suspend/resume handling and signed in-app updater artifacts.

## Privacy and security

Camera passwords remain in the native OS credential store; ordinary SQLite stores only opaque credential references. Recordings and Event history remain local. Nian Vision v1 has no cloud video upload, remote-access service or cloud notification service.

## Upgrade notes

Authoritative settings migrations preserve camera definitions, credential references, Recording/Event Desired state, PTZ/Event bindings, storage settings and notification preference. Corrupt authoritative settings are never silently replaced. Recording and Event indexes are derived and may be boundedly quarantined/rebuilt without deleting camera settings or footage.

## Known limitations

v1 requires H.264 and does not transcode or support H.265. ONVIF feature availability depends on the camera. There is no macOS/mobile release, remote/cloud access, AI/person/object detection, motion-triggered recording, generated clips/thumbnails, presets/tours/talkback, email/webhook/cloud push notifications or notification scheduling. See `docs/known-limitations.md` for the normative list.

The final `v1.0.0` tag must not be created until M15 acceptance and the clean Windows/Linux release-candidate checklist are complete.
